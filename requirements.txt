# START COMMAND. The repo file is app.py, so the module is `app`:
#
#   gunicorn app:app --workers 1 --threads 8 --bind 0.0.0.0:$PORT \
#            --timeout 120 --graceful-timeout 30 --access-logfile - \
#            --log-level info
#
#   WORKERS 1 UNTIL REDIS IS ON. With REDIS_AVAILABLE False the dedupe and
#   ghost-mute caches are per-process, so two workers answer the same patient
#   twice. v11's file suggested --workers 2, which is unsafe in the current
#   configuration.
#
#   --timeout 120 matters: R9's "SQL injection crash" was never injection.
#   gunicorn's default 30s reaper was racing the AI budget, killing the
#   worker and dropping the socket.
#
#   DO NOT set preload_app until the outbox SSL loop is diagnosed. If the
#   pool is built before fork(), parent and child share the SSL sockets and
#   libpq's record layer desynchronises — which is exactly the pair of
#   errors in the live logs ("decryption failed or bad record mac",
#   "SSL SYSCALL error: EOF detected").
#
# ── REQUIRED env vars (names verified against source) ─────────
#   DATABASE_URL            postgres://...   Render PostgreSQL
#   DATABASE_MODE           postgres
#   ENCRYPTION_KEY          python -c "import secrets; print(secrets.token_hex(32))"
#   JWT_SECRET_KEY          long random string
#   SECRET_KEY              long random string
#   GENAI_API_KEY           Gemini key (chat + embeddings + voice)
#   WHATSAPP_TOKEN          Meta permanent token
#   WHATSAPP_PHONE_ID       Meta phone number ID
#   WHATSAPP_VERIFY_TOKEN   your webhook verify string
#   WHATSAPP_APP_SECRET     Meta App -> Settings -> Basic
#
#   ★ SET REQUIRE_WEBHOOK_SIGNATURE=true TODAY. ★
#     Without an app secret the webhook accepts ANY payload, and the route is
#     rate-limit exempt because the signature was meant to be the gatekeeper.
#     Verified on v30: secret set -> unsigned and forged both 401, valid 200.
#     Secret unset + REQUIRE_WEBHOOK_SIGNATURE=true -> still 401. This flag
#     works WITHOUT Redis, unlike STRICT_PROD.
#
# ── SECOND AI PROVIDER — promoted out of OPTIONAL in R35 ──────
#
#   This is a SINGLE POINT OF FAILURE fix, not a feature. Fill ONE of the
#   two routes below. Both can be set; the chain is gemini -> openai -> claude.
#
#   ROUTE A — OpenAI-compatible slot (no OpenAI account required):
#     OPENAI_API_KEY        the provider's key
#     OPENAI_BASE_URL       blank = real OpenAI (unchanged legacy behaviour).
#                           Groq: https://api.groq.com/openai/v1
#     OPENAI_MODEL          ★ MUST be a model the chosen endpoint serves.
#                           The default gpt-4o-mini exists ONLY on OpenAI.
#                           Point base_url elsewhere and leave this alone and
#                           fallback #1 404s at the exact moment the primary
#                           dies. R35 logs a loud ❌ at boot if it catches
#                           this pairing — read the boot log, do not assume.
#
#     Why this route exists: the Gemini primary is at risk from a BILLING
#     VERIFICATION failure. Filling the fallback with another card-and-KYC
#     provider reproduces the same failure mode and is not real redundancy.
#     A no-card provider is immune to precisely what is biting right now.
#
#   ROUTE B — Anthropic (zero code change, needs a working card):
#     ANTHROPIC_API_KEY     key
#     ANTHROPIC_MODEL       default claude-haiku-4-5-20251001
#
#   BOOT LOG IS THE ACCEPTANCE TEST. You want:
#       ✅ OpenAI-compatible AI ready (Fallback #1) → <url> · model=<model>
#       🤖 AI Fallback Chain: gemini → openai
#   R35 also shouts ❌ if a key is set but its package is missing — the old
#   build failed that case SILENTLY, leaving a keyed-but-dead slot.
#
# ── RECOMMENDED ──────────────────────────────────────────────
#   REQUIRE_WEBHOOK_SIGNATURE=true   fail closed, Redis-independent
#   REDIS_URL                        Upstash free tier; unlocks workers > 1
#   OWNER_ALERT_TEMPLATE             an approved Meta utility template whose
#                                    body is "{{1}}". Without it, owner alerts
#                                    for emergency / handoff / VIP DIE SILENTLY
#                                    when the owner has not messaged in 24h
#                                    (Meta error 131047).
#   OWNER_ALERT_TEMPLATE_LANG        default en
